# Product

## Platform

web

## Stack

Existing static HTML, CSS, and JavaScript. Deployment remains static output on Hostinger.

## Users

Inferred from the current product and the redesign brief: CTOs, engineering leaders, and security leaders at teams shipping web applications and APIs quickly. They need to understand whether an application-specific security finding is real, how it was reached, and whether engineers can reproduce it.

## Product Purpose

Unbound Compute builds security research software that examines the application-specific rules a web product trusts, tests where those rules fail, and returns evidence a team can act on. The marketing site should help a first-time visitor understand the mechanism, see credible proof, and choose whether to explore a trace or apply for private access.

## Positioning

Lachesis combines source understanding with authorized runtime research, then keeps a finding at the level of proof rather than suspicion. The product is not presented as a generic checklist scanner or a fictional autonomous agent demo.

## Operating Context

Teams point the system at software they own or are authorized to test, preferably in staging or a controlled pre-production environment. The public site also includes open-source projects, browser-based security utilities, research notes, and historical CVE Casefiles at trace.unboundcompute.com.

## Capabilities and Constraints

- Preserve the Unbound Compute and Lachesis names and existing product URLs.
- Link the marketing site directly to real historical CVE investigations.
- Preserve the free browser tools as an SEO-oriented utility library.
- Do not invent customers, benchmarks, pricing, production results, or testimonials.
- The site must remain deployable as static files on Hostinger with no required application server.
- The current console demo is illustrative and must be labeled as sample data wherever it remains.

## Brand Commitments

The existing Unbound Compute name, boundary-crossing concept, evidence-oriented language, open-source work, and Lachesis Casefiles are confirmed brand assets. The existing dark interface is treated as an anti-reference for the marketing redesign, not as a binding visual rule.

## Evidence on Hand

- Real Lachesis source and runtime evidence in the linked historical CVE Casefiles.
- Existing Lachesis demo assets: lachesis-demo.mp4 and lachesis-demo-poster.png.
- Existing product pages for Lachesis, Atropos, Security Agent Skills, open source, trust, research, and design partners.
- Free client-side security tools under tools/.
- No confirmed customer logos, testimonials, benchmarks, pricing, or public production metrics.

## Product Principles

- Show the mechanism before making the claim.
- Separate historical knowledge from what Lachesis established.
- Make proof readable to engineers and decision-makers.
- Keep authorization, scope, and safety visible.
- Let one clear next action lead each page.

## Accessibility & Inclusion

The redesigned marketing surface should meet WCAG AA expectations for text contrast, keyboard navigation, focus visibility, reduced motion, touch targets, form labeling, and responsive text scaling.
